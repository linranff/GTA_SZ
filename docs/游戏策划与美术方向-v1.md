# 深城纪：下班以后

更新：2026-09-05。当前版本以本文件为准，替代早期 UE 优先、工程师主角和大城市一次铺开的方案。

> 开发状态已前进：第一个网页可玩片段已经实现。本文中的“尚无可运行版本”是策划制定时的历史状态；实际功能、实测结果和仍有的差距以《开发记录-v0.1.md》及其关联报告为准。

## 一句话与传播点

**在深圳打工，攒钱，交朋友，把下班后的生活一点点变成自己想要的样子。**

第三人称城市生活游戏，浏览器先玩。让人愿意分享的三个瞬间：第一笔日结到账；回到自己亲手改善的出租屋；在加班、赚钱、朋友和约会之间做出属于自己的选择。世界可以有压力，游玩本身要有好操作、机智选择和可见回报。

工作名《深城纪：下班以后》。宣传依靠自己的角色、城市与玩法，正式名称不使用 GTA 商标。首轮概念图是虚构游戏的美术目标，不能当作深圳当前实景或已经做出的实机画面。

## 三种人生起点

| 视角 | 具体身份与矛盾 | 可操作的乐趣 | 成长方向 |
|---|---|---|---|
| 日结打工者 | 28 岁陈野，做临时分拣、装卸、活动撤场；想攒下足够的钱，让自己有资格歇一天 | 看班次与路线、识别订单条件、装载组合、熟练操作连击、与搭档协作 | 更好工具、靠谱联系人、更合适的班次、存款安全垫 |
| 年轻职场人士 | 26 岁林夏，普通品牌运营；临下班的需求、通勤与一场约会挤在同一个晚上 | 有限信息下安排优先级、短对话谈边界、通勤路线选择、观察约会对象真正需要什么 | 工作熟练度、稳定作息、表达与关系、舒适住处 |
| 城市工人 | 39 岁何志，仓配中心装卸与短途配送工；熟悉城市后台，也有自己的爱好和约定 | 手推车转向与惯性、货物摆放、窄路选择、搭档配合、短距离骑行 | 省力设备、班组默契、可靠路线、休息时间 |

名字与年龄是创作暂定值。所有恋爱角色均为成年人。第一版以日结视角可玩，另外两种视角通过有独立目标的 NPC 出场，后续才展开各自章节，避免首版同时制作三套完整职业。

“三和大神”作为用户提出的文化参考，表现临工生活、选择与幽默，不把人群写成懒惰、猎奇的固定标签。故事设在当代，龙华相关场景先做虚构组合街区；历史三和资料与今天的现场外观分别标注。城市工人也不只作为街头背景。

## 核心循环：工作带来钱，钱带来可感知的自由

选一个今天的小目标 → 接一段有操作乐趣的工作 → 到账并结算明确成本 → 在城市里吃饭、买东西、相遇 → 改善住处或工具 → 获得新的路线、时间和选择。

每一段工作建议 2–4 分钟，采用“操作熟练 + 路线判断 + 一个突发状况”，避免把真实数小时劳动原样搬入游戏。第一次游玩 3 分钟内有一次操作成功与反馈，12–15 分钟内完成一次到账、消费升级和关系选择。

三个相互制约但不繁琐的资源：钱、可支配时间、精力。压力作为剧情状态表达，不再堆十个每日衰减条。结算界面分清收入、开销和实际存下的钱。

### 钱到账的爽点

- 过程能预见回报：接活时明确基础报酬、质量奖励、交通成本与额外时间。
- 高质量连击叠加熟练奖励，但失误不吞掉已经完成部分的基础收入。
- 存钱目标显示“还差一班”与实物轮廓；达成时可以马上去买、摆放并使用。
- 工具提升改变手感：好车刹车更稳、运输箱更容易配重、雨衣降低雨天操作干扰。
- 生活升级改变可用时间：床垫改善休息，冰箱让备餐更方便，搬近工作地点缩短通勤。
- 连续选择更好的路线与搭档，形成“熟路 + 稳装 + 默契”的组合反馈；不给无限滚雪球的复利漏洞。

### 数值第一稿

以下全部为压缩后的游戏测试数值，不是深圳真实工资、租金或商品报价。以后根据实玩调整。

| 项目 | 暂定数值 | 体验用途 |
|---|---:|---|
| 初始现金 | 180 | 能做选择，不是开局立刻陷入无解状态 |
| 一次代表一天的主班次 | 280 基础报酬，最高 40 质量奖励 | 完成操作有稳定收益 |
| 折算的一日住宿、餐食与出行 | 60 + 35 + 12 | 基础班次可净存 173，费用提前可见 |
| 实用雨衣 | 60 | 第一局就能获得的工具改善 |
| 好一点的二手床垫 | 260 | 约两个主班次可完成的小目标 |
| 二手通勤车 | 480 | 几次游玩后的路线与手感升级 |
| 第一笔安全垫 | 1,000 | 允许选择休息、拒绝不合适工作 |

无奖励普通班次的示例：180 + 280 − 107 = 353，买雨衣后余额 293。收支计算与实物拥有状态必须可读、可存档，不用只涨数字的假升级。

额外加班是可选分支，不是长期唯一最优解。休息、赴约和帮朋友也提供新的关系、路线或体验；错过一个晚上可以再约，避免永久坏结局逼玩家查攻略。

## 首章故事：《这次别说改天》

故事跨度一周。三个人在同一家快餐店见过很多次，却总说“改天一起吃”。周日是一个普通朋友准备离开深圳的日子，大家约定去海边坐一会儿。主线不靠阴谋推动，靠不断推迟的小约定累积情绪。

1. **周一，到账。** 陈野在撤场工作中学会分拣与装载。林夏来取落下的活动物料，何志是合作搭档。同一件事让三个视角自然交汇。
2. **周二，下雨。** 一段短途运输出现积水，绕行更稳但花时间。玩家可以借到雨具，也可以记住替别人挡雨的一件小事。
3. **周三，有窗的房间。** 在二手店发现合适的家具。买下、搬回、摆放，第一次看到“我的地方”发生变化；家具交易是简短选择，不是重复砍价刷钱。
4. **周四，临时加个班。** 林夏面对临下班的新需求。先补充关键信息、协商交付、求助同事或接受加班，后续反应由实际选择决定；不会给出永远正确的万能话术。
5. **周五，记得你说过。** 一次夜宵和短途散步。记住对方的偏好与已经答应的事情，比昂贵礼物更有效。对话可以幽默、笨拙，也可以选择只做朋友。
6. **周六，再存一点。** 看得见的储蓄目标已经接近，临时好班次与朋友求助发生冲突。帮人也能换来可信任的搭档，但不会自动发放比劳动更高的“道德奖金”。
7. **周日，深圳湾。** 根据时间、关系与此前约定，海边出现不同的同行者、对白和照片。有人留下，有人离开；玩家仍能继续过日子。

恋爱不是消费后购买好感。双方有日程、偏好和边界；共同经历、记住约定、坦诚沟通构成关系进展。保留朋友线与独处线，女性角色有独立工作与决定。

## 12–15 分钟网页首发片段

首发只做“周一傍晚”：一段 80–120 米精修城中村街道、一个小型仓配工作点、一间可以进出的出租屋、四位主要 NPC。另做短小的深圳湾片尾体验，采用明确的乘车转场，不伪装成已经复刻全深圳。

| 时间 | 玩家行为 | 验证的乐趣 |
|---|---|---|
| 0–2 分钟 | 走出工作点，接到撤场尾单，认识搭档 | 城市可信，目标清楚，操作马上可用 |
| 2–6 分钟 | 读标签、组合装载、推车过弯、处理一次路线变化 | 熟练与机智带来连击回报 |
| 6–8 分钟 | 手机到账；看清成本与净存；挑一件实用升级 | 钱有重量，升级立即可用 |
| 8–11 分钟 | 夜宵短对话；选择再接一单或按约出发 | 选择改变当天的体验 |
| 11–15 分钟 | 回屋摆好新物件，或转场深圳湾见面；自动保存 | 生活改变可看见，愿意再玩一天 |

这是一段连续短体验的制作目标，目前尚无可运行版本。首轮概念图优先于代码与场景扩张。

## 美术基准

关键词：**当代、克制、细节可信、有人生活、下班后的暖意**。

1. 城中村：灰白瓷砖、层次完整的窗洞、防盗网、空调、排水、便利店与快餐店；正常维护与使用痕迹并存。拒绝全画面褐色怀旧、刻意污损和低模方块。
2. 深圳湾：开阔岸线、铺装与海堤、亚热带植物、有辨识度且尺度克制的天际线。春笋等地标需要独立建模和视线核验。
3. 出租屋：同一个空间通过家具、布料、灯光和生活痕迹改善；镜头对齐，让升级一眼可见。
4. 当代线索：手机与移动支付、快递柜、普通电动车、工牌与便当。不要用满城霓虹代替深圳辨识度。
5. 近景必须有真实几何：门窗凹进、窗框厚度、路沿倒角、空调支架。重复细节使用模块化和实例化，但外观不能是方块占位。

首轮目标图与提示词保存在 `output/art-direction/`。城中村采用 v2，中性颜色校正后更符合当代生活；v1 保留为迭代记录。深圳湾是压缩游戏构图，不承诺真实摄影机位。出租屋双联图的细部透视并非精确测量，后续以同一 Blender 房间、相同相机真正实现一致。

## 技术路线与 60fps 验收

**Blender → GLB/glTF → TypeScript + Babylon.js → 桌面浏览器。** UE 作为未来可重新评估的选项。首版 WebGL2 做兼容基线，WebGPU 单独验证后再启用。Babylon 官方列出 WebGL2/WebGPU、PBR、glTF 导入、LOD 与实例化能力；这些是选型依据，不是本项目性能已达标的证据。[官方功能表](https://www.babylonjs.com/specifications/)

Blender 负责几何、UV、贴图烘焙、LOD、碰撞代理、动画与固定对照相机。程序材质必须烘焙成可移植贴图，必要时在 Babylon 重建特定材质；导入后验证方向、比例和外观。游戏规则、存档与 UI 由 TypeScript 实现，首版 IndexedDB 本地保存，不让实时生成模型成为每帧或每次对话的运行依赖。

### 首段预算假设，待实测修订

- 目标设备：用户的 M1 Max / 64 GB；桌面 Safari 与 Chrome 分别记录实际版本。
- 基准内部渲染分辨率：1920×1080，明确记录 devicePixelRatio 与画质设置；不把 Retina 全分辨率默认当作同一工作量。
- 帧时间预算：16.67ms。初始目标 GPU 留在 12ms 左右、CPU 主线程在 8ms 左右，两者可能重叠，不能机械相加算帧率。
- 首段先按可见 50–90 万三角形、约 150–250 个 draw call、6–10 位可见活动 NPC 试做。这些数字是优化起点，不是自动达成 60fps 的保证。
- 近景材质通常 1K–2K，关键资产根据实际屏幕占比决定；纹理压缩、合理 mipmap，避免每栋楼都有多张独享 4K 图。
- 固定傍晚时段先做烘焙间接光 + 环境光 + 一盏主要动态投影光。海面与湿地面使用受控的环境反射；先不把实时光追、全城实时昼夜或多层屏幕反射作为视觉基础。
- 80–120 米精修区、室内与滨海小区块分别加载。首包压缩目标 ≤35 MB，后续资源分块；解压后的内存需另外测量。

### 对照与性能必须一起通过

1. 从概念图确定第三人称机位、地平线、主路宽度、三处近景细节与颜色基准；概念中的错误建筑结构不照抄。
2. 首先制作两栋完整立面、一段可走街道、店面与主角，再进入网页；宁可减少街长，也保留可近看的资产质量。
3. 用同机位网页截图与目标图并排比较：建筑比例、材料、光照、人物尺度、可行走空间。概念图视觉接近度由人审阅，不伪造一个客观百分比。
4. 固定路线走/骑/转身/进入室内，并让 NPC 与任务系统正常运行；预热后记录 5 分钟帧时间、p50/p95/p99、明显卡顿和内存。首次加载与区块切换另测，不藏在平均值里。
5. 60Hz 测试显示平均 ≥59fps、p95 帧间隔 ≤18ms、p99 ≤25ms、无反复 >50ms 卡顿，作为首版“稳定 60fps 附近”的暂定验收线。若采用更严格的逐帧 16.67ms 要求，应另行记录；不得把两者混称。
6. 瓶颈在哪就调整哪：材质批次、贴图、LOD、阴影、植被覆盖、NPC 更新频率；每次优化后同时复查截图。
7. 通过 M1 Max 验收也不等于所有 Windows PC 达标；Windows 必须在明确硬件上另测。Steam 封装、平台存档、手柄与发行是后续工作。

当前状态：概念图制作与策划已开展，尚未建成上述可玩场景，尚无实机截图或 60fps 测量结果。图像生成接口未公开本次模型标识；不能宣称图由指定的 2 或 2.5 生成。官方已确认存在 [GPT Image 2](https://developers.openai.com/api/docs/models/gpt-image-2)。
