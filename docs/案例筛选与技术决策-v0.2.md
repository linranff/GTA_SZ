# 案例筛选与技术决策 · 2026-09-05

当前决策：Blender 5.2 制作可编辑建筑、地标、树木和车辆；Babylon.js 8 + TypeScript 在浏览器运行。保留地图、资产和玩法代码的分离，后续是否进入 UE5 由目标平台与实测画面决定。

Blender 是资产制作工具，不是我们这次的运行引擎。Three.js 和 Babylon.js 都能运行浏览器 3D；本项目已经使用 Babylon.js，转换库不会自动改善美术。当前缺口主要是地标细节、建筑类型、真实高程、街景密度和交通行为。

UE5 更适合未来以桌面客户端为主、需要其完整场景工具链的阶段。Epic 的浏览器方案 Pixel Streaming 是将引擎画面串流到浏览器，需要运行引擎的主机；这不同于当前网页自行执行游戏。因此当前不为了网页试玩改用 UE5。

来源：[Epic Pixel Streaming](https://dev.epicgames.com/documentation/unreal-engine/pixel-streaming-in-unreal-engine?lang=en-US)、[Babylon.js 能力列表](https://www.babylonjs.com/specifications/)。

## 已核对的原始来源

- [Anshu 工作流](https://x.com/anshuc/status/2096008086901113339)：图像目标、Blender、实际截图迭代；[作者确认 Three.js](https://x.com/anshuc/status/2096027023982366782)。演示画面是有限范围场景，不能把其耗时直接套用于整个深圳。
- [Matt Shumer review](https://somethingbig.ai/astra-review)：曼哈顿使用 UE，文中明确项目仍在推进，并讨论现有资产与协调方式。这里借鉴的是持续验证整体进展。
- [Sunwake 官方过程](https://developers.openai.com/showcase/sunwake)：从航行手感到水面、天空、目标和 Blender 船体逐步改进。对我们最有用的是让车辆与接触表面、灯光变化保持一致。
- [Building games with Astra](https://developers.openai.com/blog/how-to-build-games-with-astra)：跨尺度的可达场景需要一起解决控制、空间和渲染。对本项目的启发是可见地标必须存在于真实游戏世界，不能用概念图背景代替。

## 之后值得做的三个玩法

1. **最后一班之后**：从写字楼接上朋友，开往深圳湾。有限的夜间时间中，在加班来电、朋友心情和自己的休息之间选择；小对话随经过的地点触发。
2. **一日一城**：连续到访滨海、香蜜湖、市民中心和罗湖，形成自己的城市相册。奖励来自探索和拍摄条件，不强迫玩家犯罪或飙车。
3. **攒到自己的车位**：日结、轮班和年轻职场三条生活线共用这座城市。积蓄带来实际可见的改变：租房、休息质量、车辆与周末自由。经济系统等驾驶和外景稳定后接入。
