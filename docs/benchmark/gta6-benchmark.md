# 深城纪 × ChrisGPT 城市飞行演示：开发对标

核查日期：2026-09-12。依据：用户下载的 9 分 50 秒视频、实际在线试玩、公开部署 JavaScript、作者公开原帖，以及深城纪当前源码、实际 GLB 和最近截图。此次只做分析，没有修改游戏实现。

**结论：值得把它作为环境美术与航拍体验的标杆。我们的主要缺口是统一的视觉标准、完整街区布置，以及让这些细节可负担的渲染组织。继续采用 Babylon.js + Blender，先完成一段可连续游玩的高质量街区，比继续全城零散加特效更有效。**

用户新增的性能要求：主目标改为 **RTX 3060、1920×1080、60 fps**。M1 Max 保留轻量档。3060 的桌面/移动版本、显存、CPU、内存尚待确认；本次没有访问该电脑，60 fps 是验收目标，尚未证明达成。用户反馈对标游戏在 M1 Max 上很卡，这说明其当前体验不满足这台电脑的需求；具体瓶颈仍需测量。

**3. 我们已有不少功能，预算却没有充分变成可见质量**

对标部署代码确认使用 Three.js r170，并定制了天空、水、色调处理、级联阴影和城市/植被 LOD。默认 `high` 配置包含 4×MSAA、3 张 2048 级联阴影、24 步体积云（宽高各按主画面 0.6 渲染），以及半分辨率、5 公里范围的平面反射；另有大气后处理和多层 bloom。这些都是潜在成本，能解释为什么需要认真分档，但本次没有 GPU 实测来确定它在 M1 Max 上的主瓶颈。它的固定画质档与 DPR 上限也不等于按帧率自动调节。

代码的 `VI.snapshot().avgFps` 根据 `render` 调用区间的 CPU 耗时换算，不能作为实际屏幕呈现帧率。后续对比使用真实帧间隔和 GPU 计时；不以项目自带指标名称判断达标。详见 [部署代码审计](/Users/fenglinran/Documents/ChatGPT/深城纪/docs/benchmark/reference-runtime-audit.md)，原始入口为 [公开部署 JS](https://gta6.love.chatgpt.site/assets/index-fgCY31YX.js)。

源码确认已有 HDR/ACES、SSAO、2048 主阴影、水面/道路平面反射、车辆局部反射与红漆 clear coat、雨天、车辆音效/BGM。能力存在不代表组合效果已成熟。当前实际主角车约 9.92 万三角面，基础楼体约 331 万、道路约 202 万；继续单纯提高面数不是优先项。

基础城市有 16,076 栋楼、12,202 条道路，游戏范围包围矩形约 13.58×5.21 公里，含水域。当前基础楼体/道路仍整体载入；有近立面分块加载与植被 LOD，但尚缺完整的远景建筑群合并简化和按渲染通道裁剪。最近性能报告约 30 fps，GPU 样本约 10–23 ms；30Hz 是否涉及呈现节奏需要复查，部分 GPU 时间也确实超过 16.67 ms。不能将它写成稳定 60 fps，也不能全部归咎于树木。详见 [当前基线](/Users/fenglinran/Documents/ChatGPT/深城纪/docs/benchmark/current-game-audit.md)。

**4. RTX 3060 的实施顺序与验收门槛**

| 阶段 | 具体交付 | 完成条件 |
| --- | --- | --- |
| P0：可复现基线 | 3060 上固定浏览器、原生 1920×1080 渲染缓冲、相机、时段、天气、资产版本；分别记录 CPU/GPU、实际帧间隔及各通道绘制成本 | 同机可重复；确认瓶颈；报告中位数、p95/p99与卡顿，不能只读平均FPS |
| P1：统一光照与材质 | 春笋、深圳湾海岸、居民街区三个固定场景；先完成晴天日间，再扩展黄昏、夜间、雨天 | 白墙、玻璃、柏油、红漆、树叶的亮度与反射可区分；阴影有方向，暗部可读，远景不糊成灰幕 |
| P2：完成一条街区路线 | 在春笋/人才公园一带选约1–1.5公里连续路线，补首层、屋顶、步道、树池、设施、植被；深圳湾公园沿海做第二个独立样段 | 驾驶、步行、低空三种视角都成立；相邻资产无明显空洞、漂浮、穿插与重复感。具体路线以道路数据确认 |
| P3：把质量装进预算 | 远景楼群合并简化（HLOD）、实例批次、距离/屏幕尺寸LOD，限制阴影和反射绘制对象；高成本效果分别降采样 | 3060 目标档连续120秒驾驶及60秒航拍，p95帧间隔以≤16.67ms为目标，记录加载峰值和p99；不通过就调整成本，不降低验收口径 |
| P4：扩大覆盖范围 | 将通过验收的街道模块、建筑原型、树形及材质规则推广到下一街区 | 每次增加覆盖都有固定镜头比较和性能回归；保住前一版已经达成的质量 |

P1/P2 必须伴随成本记录，不能到最后才开始优化。初期预算假设：稳定段 GPU 约≤12–13ms，CPU 更新/提交约≤8–10ms，以留出波动余量；两者可能并行，不能直接相加。具体数值须在目标电脑校准。

**画质分档保留同一套美术。** 3060 主档优先保住清晰的主光与阴影、车辆材质、近景树冠、海岸层次；云、反射、阴影距离分别调整成本。Mac 轻量档降低云采样/分辨率、反射范围与刷新率、远处树木和阴影精度，保留构图、配色、街道组成与关键模型。截图/录制档可以额外提高效果，但其表现不作为日常游玩性能证明。

**5. 后续协作方式**

共享渲染代码由一个集成人员维护；资产工作可以并行拆为“树形与 LOD”“建筑首层/屋顶模块”“街区布置”。每个任务绑定一组固定镜头、资产/绘制预算和验收条件。渲染人员负责太阳/天空/材质/反射一致性，集成人员负责合并后实机表现。评分用于定位问题，不用自评高分替代截图和帧时间。

当前最应该投入的，是让一条街上的建筑、地面、树木、车辆和光照共同成立。把这套标准和性能管线做通，才能逐片区可靠扩展。
