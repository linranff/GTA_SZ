## 程序化城市为什么比简单“挤出建筑”完整

`pk @584390`使用20,000米宽、2048²采样的程序地图（`so/os @561275`），构造分区、道路、桥梁、码头、跑道、河道、地标等。`JI.init`按地图—地形—道路—桥梁—建筑—人行设施—港口/机场—植被—交通—飞机依次构建，地块与道路共同影响占地掩膜。

`PR @1432426`按分区选择楼型、地块、楼层/高度、色系、功能和附近道路；`Ed @1422550`将box/cylinder/octagon/frustum/shear/house/trim/ledge/roof/vent等少量原型组合、分块、实例化。每实例携带尺寸、立面风格、层高、种子、屋顶、窗灯、色温、变体和形体字段，**大量变化来自共享几何与共享材质的参数**，而不是每栋楼一份独立高模。

`fR @1279621`不是单张窗格贴图：GLSL根据这些字段生成不同立面，包含室内视差房间、凹窗/边框、阳台/栏杆、底层店面与屋顶样式。`VC @1124787`进一步构造人行道、街树、信号与街边部件，并接收建筑groundBoxes信息。地块、首层、道路、植被之间有规则联系，这是画面“完整”的重要来源。

城市有1500米大块，再切细胞；主相机、反射和各级阴影分别合批。`Ed.updateLod`按屏幕投影尺度、距离和视锥选择房屋/细节；远处阴影可以用更少的代理体。`go @1034619`是动态实例批次分配器，只上传脏区，回收/压缩空洞。并不是把全城放进一张高模再统一裁剪。

## 植被不仅是“更多树”

`G0 @1653675`创建三档近树冠、棕榈高/低几何、主视图cards、反射cards、草和贴地草层。`I1 @1541182` / `Qu @1541784`明确构造树干、一级枝、二级枝、根系和叶簇：最高档24边树干、6根主枝、每主枝3根次枝、4组根和64簇树叶。低档减少枝/根并换成卡片，不能把这个特定几何模板当成整棵树总面数。

其树形shader包含榕树气根、阔叶根张、棕榈羽叶、不同冠型与倾斜；8类archetype各有颜色和高度分布。`eP @1638690`的部分乔木上界到22.5–25米。`G0`按海岸/红树林/公园/低层住宅等生态与城市条件种植，而不是完全均匀随机撒树。

叶片材质有实际接入的wrapped diffuse、背光透射、厚度门控、树冠内部遮蔽；树干考虑冠下天空遮蔽及地面反弹色，并用树皮法线细节。树冠的受光和树形在一起设计，这比放大同一个树模型后只改颜色更接近用户想要的质感。

`G0.updateLod @1671647`按相机位置和细胞分配几何预算；典型阈值有近冠80/420米、棕榈150/650米，cards远界9000米，3000/5500米后进一步稀释数量。反射只使用专门cards/低模，受1500米范围约束；阴影按cascade单独控制。所有数字还受质量档与类别约束，不能解释为“9公里内全部高模”。

## 没有发现基于帧率的动态分辨率

`CD @2168966`只在初始化和window resize调用尺寸函数：显式`w/h`时DPR=1，否则`min(devicePixelRatio,1.5)`。未见根据GPU时间/FPS自动改变DPR、质量档、云步数或渲染比例的反馈控制。它具有固定四档质量、视距LOD和分pass低分辨率，不应称为“动态分辨率自适应”。

## 性能自测值得借鉴，但要读对指标

`JI`提供passStats，分别统计wake/sky/shadow/reflection/main/post；可选`qI @2102009`进一步按系统、mesh和cascade做draw/triangle census。`compileShaders`先触发compile/compileAsync，`warmShaders`预演水面与空中状态，减少首次出现效果时的编译卡顿。

`VI @2100223`的`avgFps/onePercentLowFps`由`beginFrame/endFrame`之间的CPU渲染调用时间求倒数，**不是requestAnimationFrame实际呈现帧率**。其GPU query单次异步读取也可能拿不到结果。不要拿这一面板数字证明“稳定120fps”。

`aD @2134791`可固定种子、天气、镜头、模拟步长，并通过`renderSync`的`gl.finish + readPixels`测同步渲染耗时；但该计时不含之前的update，也不是交互式呈现测量。`ig`还有具名参考镜头、预模拟时间、固定相机与飞机屏幕位置，适合对比画面而非替代完整游戏性能测试。

## 对深城纪的可执行启发

主目标按用户最新指示改为**RTX3060的1080p/60fps，M1 Max保留轻量档**；3060桌面/笔记本型号、显存和CPU仍需确认，当前没有该机器的测试结果。

1. 优先借鉴“按用途分批与LOD”。我们的基础楼与道路已各有数百万三角面，不能在其上直接叠加参考作品全部pass。先把主视图、反射、阴影独立统计/裁剪，给远处楼体建立代理；节省预算后投入街面细节。
2. 街区使用共享模块和参数化立面，但为深圳保留地标轮廓和城市地理。店面、门厅、檐棚、树池、人行道、路边停放必须协同生成。不要照搬参考城市的粉彩海岛构图。
3. 树木需要树形+受光一并升级：3–5种主树型、真实分叉与根部过渡、叶片透光/冠内遮蔽、每种多变体与LOD。无需把参考的所有枝叶着色逻辑全部移植，先在完成度路线验证画面与GPU成本。
4. RTX3060标准档可研究受控的两级/三级阴影、适量动态云和局部反射；是否加入、分辨率多大以GPU时间决定。Mac轻量档优先同一美术内容，使用更便宜天空、较低反射/阴影分辨率和较小高模半径。不能通过全局压暗/浓雾来隐藏降档。
5. 建立真实的帧时间验收：同一1080p、相同镜头/路线/天气；记录rAF分布、GPU时间、update/submit、每pass draws和内存，连续驾驶至少120秒。参考作品自测体系的可重复镜头很有价值，其“fps”名称不能原样照搬。

它提供的最大启发是：大量品质来自对每一种材料、城市尺度和渲染pass进行专门处理，并让参数相互一致。画面精致与成本增加同时成立；我们的目标应该是学习这套组织方法，为目标硬件选择效果，而不是把重效果全开后宣称对标完成。
