# 资产重建与交付保护

本轮修正了两个会让后续工作退回旧版本的入口。

`rebuild_city_assets.mjs` 原来直接逐阶段覆盖当前 `public/city`：车辆回到旧程序模型，普通楼回到两个全城模板，新植物未构建；中间任一步失败也会留下半新半旧的可玩目录。现改为在 `artifacts/rebuilds/<时间>-<进程>/` 内复制源输入并执行源脚本，**整个流程不会替换当前已审查的 `public/city`**。

`finalize_city_assets.mjs` 原来只扫描顶层GLB，并把旧作者报告的三角数写给新资产。现从实际GLB JSON accessor计数，递归记录植物、道路细节、贴图和元数据。新车使用运行时实际读取的 `car.glb`，并将字节数、SHA、三角数与 `vehicle-manifest.json.delivery` 交叉核对。普通楼UV2存在时必须有两张图集。流式立面依然检查源GLB和每块的SHA/字节数。

## 命令

```sh
# 只读：打印源依赖与完整步骤，不复制/重建资产。
npm run assets -- --plan

# 源重建：创建隔离候选目录；不发布、不影响当前试玩。
npm run assets

# 只读：核对当前交付，包含新车/植物/立面图集。
node scripts/finalize_city_assets.mjs --check

# 集成人员已串行安装并核对资产后，更新三个交付manifest。
node scripts/finalize_city_assets.mjs
```

隔离流程使用已存在的城市OSM数据、地标证据和DEM缓存、保存的原创贴图源图、已核对许可/哈希的 CarConcept 原始GLB。车辆源哈希发生变化时停止，不把它默认为原来已审查的来源。Python、Blender和Node依赖仍使用本机安装，不重复下载。源脚本中相对于脚本位置的写入路径会解析到隔离目录。

三项新资产按以下依赖重新生成，**不直接复用上一轮候选GLB**：

1. 普通楼原始几何 → Meshopt → OSM排除ID更新 → COLOR_0修复 → 从OSM用途生成UV2家族/相位 → 八族手工图集 → 安装到隔离场景。
2. CarConcept原始GLB → Blender细化/降面/轮轴导出 → 清除variant与优化 → 安装隔离`car.glb`及对应metadata。交通车辆仍由旧轻量原型单独生成。
3. 植被/道路细节 prepare（材质、种植排除）→ Blender原型 → 近远景植物及路面细节 → 清单校验。

原有三张建筑备用图也从已保存的原图重新缩放并生成对齐窗灯mask。新增流程范围以 `--plan` 输出为准；其他已有交付文件是被保留的输入，不宣称都从零重新生成。后续新资产要么补入源步骤，要么在记录中明确作为保留输入。

完成时 `build-status.json` 为 `candidate-ready`；失败时为 `failed`，记录出错命令并保留候选供排查。`candidate-ready` 只表示源命令和结构检查通过，**不能据此宣称画面、真实还原或FPS通过**。应在单独预览中复核当前机位、驾驶/无人机控制、车轮与灯光、路面种植排除及持续帧时间后，再由集成人员串行安装所需产物并finalize。当前脚本不提供自动发布开关。

本轮只运行了 `--plan` 与当前资产 `--check`；全量隔离重建尚未端到端执行。当前交付目录及模型未被本次脚本审计修改。
