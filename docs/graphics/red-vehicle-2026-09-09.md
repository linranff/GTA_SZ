# 绯红海湾 GT · 2026-09-09

主角车改为深红色，并集中修复车身曲面、清漆高光与街景反射。沿用 CarConcept 的模型来源与 CC BY 4.0 署名。游戏控制、轮轴、车灯及既有城市资产保持兼容。

## 最终改动

- 车漆：sRGB `#B91925` 明确转为线性颜色；红色底漆与中性的清漆层分别调校。金属度 0.25、底漆粗糙度 0.30、清漆粗糙度 0.12、清漆折射率 1.5；减弱微法线颗粒，环境强度 0.8。玻璃改为中性深色。
- 光照：删除跟着镜头移动的主角车补光灯。车辆使用场景阳光、天空环境光和路灯，转动镜头不会移动照明。
- 几何：不再对源模型的主要 Paint 1 外壳、车顶、引擎盖上格栅和风挡减面；轮圈、机械及内部部件继续使用原预算策略。总三角面从 78,825 到 99,194；GLB 从 2,143,520 到 2,521,248 bytes；维持 26 个网格组。未对整车盲目细分，也未重建城市。
- 牌照：根据保留后的源曲面重新投影，网格改为 64×24，外移 12 mm，消除牌照与新曲面的穿插；仍为“深城纪”。
- 局部反射：一个 128×128/面的 HDR 立方体，最多 29 个网格（含天空）、90,000 三角面，并逐面剔除视锥外对象。只影响主角车漆与玻璃，不收录自身、交通车、行人或实例化树群。
- 反射调度：位移至少 2 个游戏单位、距上次调度至少 0.5 秒才申请更新；光照环境改变时重新采集。停车后转镜头不重新采集，观察距离超过 65 个游戏单位时使用全局 HDR。初次着色器预热/新材料就绪可能产生额外引擎重试，诊断同时记录实际捕捉次数，不能把 2 Hz 调度目标当成绝对 GPU 提交上限。
- 反射过滤：普通动态立方体 mipmap 不等于 GGX 预过滤环境，因此仅在这两个主角材质使用 8 样本实时过滤；回退全局已预过滤 HDR 时关闭。
- 反射天空使用独立渲染通道材质，不来回更换主场景天空材质。只有完成六面实际绘制后才向主角材质暴露反射图。

这是有限范围、低频的近景反射，并非全场景逐帧光追。远处景物仍由全局环境提供；其他移动人物/车辆不会出现在这张局部环境图里。

## 验证

- `npm test`：172 项通过。
- `npm run build`：通过，保留既有大包体提示。
- `node scripts/check_vehicle_delivery.mjs`：当前 public GLB 哈希、四个轮轴/轮胎圆度、转向制动组、灯组发光等检查通过，无错误与警告。
- `node scripts/inspect-red-vehicle.mjs`：实际游戏三种光照、前后两个角度的 6 张截图；7 项浏览器行为检查通过，包括真实行驶、反射预算、转镜头不捕捉、远景停用、牌照与运动套件挂接、移除镜头补光。无页面/渲染错误。
- 测试场景为初始滨海大道附近，Chrome / ANGLE Metal，1920×1080。三个固定观察视角平均约 60 fps。以下为最终同起点、10 秒真实油门行驶对比；交通状态存在时序差异，不能把约 0.2 fps 的差异解释为优化收益。

| 配置 | 平均 fps | 95% 帧时间 |
| --- | ---: | ---: |
| 新红车，局部反射关闭 | 59.76 | 18.0 ms |

结果支持这条测试路线未出现明显性能退步，不代表整座城市所有路段稳定 60 fps。测量明细包含实际捕捉次数和几何数量，见 [最终报告](../../output/playwright/red-vehicle/after/report.json)。

## 复现入口

1. `Blender --background --python scripts/build_vehicle_candidate.py -- --asset-only` 生成候选，跳过离线摄影棚渲染。
2. `node scripts/optimize_vehicle_candidate.mjs` 整理网格及交付哈希。
3. `node scripts/check_vehicle_delivery.mjs --candidate` 验证候选；通过后将候选 GLB 与 manifest 一起复制到 public 对应文件，并运行正式检查。
4. 使用上述浏览器脚本检查外观、驾驶和性能；候选文件沿用历史文件名 `indigo-gt.glb`，材质已是红色。
