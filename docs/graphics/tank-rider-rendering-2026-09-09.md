# 坦克、骑手、咖啡厅动作与渲染修复

2026-09-09。本轮在现有城市中加入用户提供的坦克和骑手资产，并修复动态模型加载导致的车辆、城市漏绘。开发地址为 `http://127.0.0.1:5173/`；当前开发配置关闭热更新，修改后需要刷新页面。

## 已实现的操作

| 状态 | 操作 |
| --- | --- |
| 驾驶 | T 在轿车和坦克之间切换；空间不足时拒绝切换或调整到附近可容纳的路面 |
| 坦克 | WASD 驾驶，Q/E 转炮塔，PageUp/PageDown 调炮管，空格开炮，X 刹车；炮弹命中建筑/地面复用飞机多重火球效果 |
| 上下车 | F 下车；回到车辆附近按 F 上车。轿车和坦克均可下车 |
| 步行 | WASD 行走，Shift 跑步，C 第一/第三人称切换，拖动调整朝向 |
| 无人机 | G 进入；底部 WASD 栏的小按钮 B 飞机进入飞行，B 返回无人机。移除顶部大切换卡片 |
| 咖啡厅 | 三位店员各自巡游，玩家靠近时停步、转向并招手，E 与移动后的店员交谈 |

坦克炮弹有飞行轨迹、重力、连续碰撞检测和 1.8 秒装填时间，最多四颗弹体、两组复用爆炸。此版本没有建筑结构破坏。坦克履带仍为静态模型；炮塔、炮管和后坐可以运动。

## 漏绘原因与处理

实际追踪发现 Babylon 8.56.2 的 glTF 加载收尾会将场景中已有材质的 `maxSimultaneousLights` 全部抬升到场景灯光数。立面分块、人物和坦克的异步加载因此会引发已有城市和车辆的大批着色器重编译。

`city-gltf-streaming.ts` 使用加载扩展生命周期保留已有材质灯光预算，不改 node_modules。新资产仍由其材质设置处理；加载期间的合法日夜/局部灯光变更会被保留。

车辆还有局部灯光槽位变化、PCF 阴影列表清空导致的变体切换。为主车保留固定灯光预算及阴影变体；没有有效局部光时以零强度和空实际绘制列表保持状态，避免车身、玻璃短暂跳过绘制。高空效果切换增加 125–165 m 回差，降低临界高度反复切换。

## 性能与后台进程

1600×1000、独立 headless Chrome / Metal、保留用户后台程序，每阶段短采样。不是 Codex 内置浏览器实测，也不是长时间压力测试。

| 场景 | 修改前平均 FPS | 修改后平均 FPS | 修改后帧时 P95 |
| --- | ---: | ---: | ---: |
| 驾驶 | 42.2 | 49.6 | 26.2 ms |
| 高空转向 | 52.0 | 53.3 | 25.7 ms |

修改后驾驶采样末端约 916 draw calls、430 万三角面，CPU 渲染提交约 14.4 ms，GPU 约 13.2 ms。这两个时间有重叠，不能相加当作总帧时。后台与转向造成可见物变化，前后数字只作现场观察，不能把差值全部归因于单一修复。关闭反射的探索采样视角不同，不作严格 A/B 结论；没有宣称稳定 60 FPS。

18:15 的进程快照没有 UE5 Editor 或 ShaderCompileWorker，只见 `UnrealEditorServices` 0.0% CPU、约 22 MB。WindowServer 49.4%、微信辅助进程 20.8%、Codex Service 19.6%（CPU 百分比按一个核心计）。整机 GPU 利用率快照约 60%，无法从该指标分配到单个程序。没有关闭用户程序。后台负载和游戏渲染开销都存在，不能归因于已退出的 UE5。
