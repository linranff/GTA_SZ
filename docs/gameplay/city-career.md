# 下班后的深圳：本轮职业玩法

这是一段可以重复游玩的城市生活原型。三种身份提供三种不同操作目标，而不是只改变订单文案。它尚未包含完整的开放世界 AI、室内生活、自由恋爱模拟或 GTA 级叙事规模。

| 身份 | 首份合约 | 操作差别 | 进阶合约 |
| --- | --- | --- | --- |
| 日结打工者 | 热饭趁热送 | 到驿站领餐，实际行驶送餐；时限后逐渐损失品质，不抹掉已经完成的劳动报酬 | 两站连送：两站共用时限，整轮完成才结账 |
| 年轻职场人 | 把十分钟还给自己 | 接上阿琳，平稳驾驶；急刹和急转扣舒适度，速度本身不直接加分 | 今天准点离开：到办公室接人，关系与驾驶品质影响奖励 |
| 城市工人 | 雨后巡检 | 领巡检单，海边与公园逐站停车作业；移动打断工时，完成作业条后按 E 交接 | 城市亮灯之前：维修站领设备，多处照明设施巡检 |

三个基础合约都从出生地附近的生活驿站开始。世界集成将 `bay` 设在约 700–1,500 游戏米外，使第一次报酬能在几分钟内获得。地点坐标属于世界集成层；玩法核心不硬编码深圳经纬度。

每完成一份合约得到 100 经验，某身份完成两份后达到 2 级并解锁该身份的进阶合约。合约可重复，无真实日历、体力门槛或等待付费墙。切换身份不清空经济或各身份进度。一级基础报酬为 ¥190 / ¥230 / ¥260；实际结算 = 基础报酬 × (0.65 + 0.65 × 品质比例)，再加补给、关系和工具奖金。正常品质 100 时约 ¥247 / ¥299 / ¥338。

## 收入、消费与关系

- 保温配送箱 ¥420：配送时限增加 35%，迟到品质损失减半。
- 座椅与缓冲套件 ¥560：急刹、急转的舒适损失减少 45%。
- 便携巡检工具 ¥390：每站工时缩短 40%，完成工人合约增加 ¥25 补贴。
- 自己的房间基金 ¥1,800：从钱包扣除并锁定安居金，后续所有合约增加 8% 稳定奖励。本轮仅记录基金，不代表已经建造可进入的房间。
- 驿站补给 ¥18：需要实际在驿站 40 米内停稳；下一份合约舒适损失减少 15%，完成后得到 ¥18 补给奖励，取消合约不返还消耗的补给。

每个身份第一次和第三次完成合约会触发一段有后果的角色消息。选择可以花钱请热饭/咖啡，也始终有不花钱的有效回应。关系数值会提高之后的关系奖金（每点 +¥4）。阿琳的第三段消息可以选择认真约会或保持友谊；这是关系分支的第一步，不能称为已完成完整恋爱系统。选择结果、关系、收入、工具、进阶等级均持久保存。

## 接口

纯逻辑文件：`src/city-career.ts`。不引用 DOM、渲染器、真实时钟或 localStorage。

```ts
const career = new CareerGame(
  {hub, bay, office, park, workshop}, // 每个为 [x, z]
  readCareerSave(savedCareerV2, previousLifeV1),
);
const frame = {
  dt, position: [playerX, playerZ], speed, odometer, debugEpoch,
  yaw, inVehicle: !onFoot, paused: mapOpen || observerActive || journalOpen,
};
const events = career.tick(frame);
const active = career.active; // 当前导航目标 active.objective.position
const prompt = career.prompt(frame);
const action = career.interact(frame); // 停车按 E
localStorage.setItem(CAREER_SAVE_KEY, JSON.stringify(career.save));
```

`selectRole(role)`、`accept(jobId, frame)`、`interact(frame)`、`cancel()`、`purchase(upgradeId)`、`choose(optionId)`、`replenish(frame)` 均返回 `{ok, message, events}`。失败结果不会修改钱包或重复结算。`tick(frame)` 返回事件数组。`view` 包含当前身份、三个身份卡、当前身份的合约、解锁状态、等级/经验、升级物品、关系与等待回复的消息。`save` 是副本，不能通过修改 getter 返回值改变内部钱包。

速度单位是游戏米/秒；yaw 为弧度。步行可提供角色位置和 speed=0、inVehicle=false，里程仍保持车辆里程。职场接送的每段需要足够实际车辆行程，防止步行冒充接送；到站后可以下车交谈。菜单和无人机暂停计时和巡检；`debugEpoch` 必须在地图瞬移、车辆回路重置等非连续位置变化时递增。反常位置突变、调试跳转、车辆里程倒退都会让本单失去结算资格，重新接单可以恢复正常体验。这里是原型防误结算，不是对抗修改浏览器 JS 的安全系统。

每个目标需要 28 米内、绝对速度小于 1，第一站之后还需要本段有足够实际位移。巡检按站连续计时，不能在移动中或菜单里完成。两站订单中途不发钱，最后一站统一支付。同一合约完成后立刻移除运行状态，重复 E 不重复给钱。

旧三条顺路故事可以保留为另一页签。用 `creditLegacy(rideId, amount)` 将其结算同步到新钱包；迁移时旧 `completed` 已进入 `legacyCompleted`，因此不会再次发旧奖励。不要同时使用两个不相干的钱包。持久存档只保存已完成事件，活动合约不跨页面重载恢复，从而避免载入旧路线或旧里程造成错误结算。

## 本轮验证

`node --experimental-transform-types --test tests/city-career.test.ts`：10 项测试覆盖迁移和旧奖励防重复、三身份初始入口和进阶、接送要求真实车辆行程、调试跳转/位置突变/里程重置、分段交接与停车、巡检连续工时和暂停、保温箱时效、舒适升级实际效果、选择持久化与支付、实际补给位置与房间基金奖励。

这些是玩法逻辑测试，不代表 UI、世界标记或 Blender 资产外观已通过验收。世界集成人员需再做短的功能和视觉检查；本轮不依赖持续帧率压测。
