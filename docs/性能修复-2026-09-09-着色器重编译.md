# 2026-09-09 驾驶与切换载具时的 1–2 秒卡顿修复

用户报告 `main` 3104cdf 上开车、切换载具会卡顿一两秒，卡顿瞬间地图出现一片空白亮光。已在本机 Chrome（Metal WebGL2，1920×1080，正式构建）复现并定位：所有长停顿都是**同步着色器重编译**。Babylon PBR 程序按"影响该网格的灯光集合 + 材质开关"取键，任何一项变化都会让受影响材质全部重编；编译期间材质未就绪的网格被跳过不画，天空从缺口透出，就是用户看到的"空白一片光"。

## 触发源（按停顿时长排序）

- 切换坦克/飞机时禁用轿车节点，挂在其下的两只头灯和尾部路面灯一起被禁用；每辆车周围所有材质的灯光布局改变。基线一次切换重编 73–121 个程序，主线程停 0.6–1.1 s ×2 帧，单帧最多跳过 366 个子网格。
- `city-local-lighting.ts` 旧实现在驾驶途中反复改 `includedOnlyMeshes`、开关灯、改 `shadowEnabled` 和 `maxSimultaneousLights`，每次都是一轮重编。
- `city-gltf-streaming.ts`：Babylon 8.56 的 glTF 加载器在**任意** GLB 完成时把场景内所有材质的 `maxSimultaneousLights` 提到 `scene.lights.length`。立面分区、坦克、飞机流入都会把全城材质标脏一次并恢复一次。
- 高空全景切换 MSAA/FXAA 会重建两次后处理链，每次重建让 `applyByPostProcess` 翻转两次，每次翻转 `markAllMaterialsAsDirty`（本城约 35 ms/次）。
- 竹林咖啡馆室内灯随距离 `setEnabled`，经过时重编周边材质。

## 处理

- `city-world.ts`：新增永不禁用的 `vehicle-light-rig`，头灯和尾部路面灯挂在它上面；每帧把位姿同步到当前驾驶的车或坦克，坦克用车体前部锚点 `TANK_HEADLIGHT_ANCHORS`。坦克时尾部路面灯按强度归零，不禁用。
- `city-local-lighting.ts` 改为"着色器稳定契约"：两盏灯常开、用强度表现开关；接收列表按网格一次性分类（静态几何按距任一灯位 range+8 m，行人/车辆按身份），只增不改；PCF 槽常驻编译，用空绘制列表表现关闭；材质灯光预算一次抬到固定值。单元测试改为断言灯光 define 布局在驾驶、切模式、过区域时不变。
- `city-gltf-streaming.ts`：在 `PBRMaterial`/`StandardMaterial`/`BackgroundMaterial` 原型上拦截 `maxSimultaneousLights` setter；加载窗口内的写入不标脏，`onReady` 恢复预算后只对与加载前基线**净变化**的材质补一次 `LightDirtyFlag`。
- `city-cinematic.ts`：`applyAntiAliasing` 一次 `prepare()` 同时应用 MSAA 与 FXAA，重建期间 `_forceBlockMaterialDirtyMechanism(true)`，事后确认四次 `markAllMaterialsAsDirty` 全部被拦下（0 ms）。
- `city-bamboo-cafe.ts`：室内灯用强度归零代替 `setEnabled`。

## 验证（同一脚本序列，基线与修复各跑一遍，1920×1080，无痕 Chrome）

序列：地图自动驾驶去平安 40 s（日落）→ 切夜色 20 s → 坦克开/驶 8 s/关 → 高空 + 飞机起飞/降落 → 传送深圳湾公园 → 夜间手动驾驶 25 s。原始数据在 `artifacts/city/shader-hitch-2026-09-09/`（基线为 3104cdf 另建 worktree 构建，仅加入同样的编译计数诊断字段）。

材质未就绪导致的缺口（在 `isReadyForSubMesh` 上计数，夜色、原地切换两轮）：基线坦克开一帧跳过 366 个子网格、坦克关 324、高空开 201、高空关 139；修复后坦克关 0，坦克开首次一帧跳过 23（坦克自身材质首编，31 ms 帧），第二轮全部为 0，高空开首次一帧 66（高空专用变体首编，82 ms），之后 ≤1。

稳态没有变化：同一路段自动驾驶夜景，基线与修复后均约 54–55 FPS，GPU 约 14.7 ms，CPU 提交约 15 ms，约 1150 次 draw call；本次不改变稠密路段的帧率上限。
