## 本轮全部在 Cursor 执行

代码、Blender 构建、资料和候选模型在 Cursor 的同一项目环境完成，不为不同任务复制一份未知版本的仓库。Grok Bot 保留为以后独立资料任务的可选入口，本轮尚未派发 Bot 任务。

| 执行者 | 首批任务 | 交付与结束条件 |
| --- | --- | --- |
| Cursor / Grok 4.6 Extra High（工具与建模） | 候选导出脚本；冻结规格后的建模模块；参数变体；确定性测试与批处理工具 | 允许范围内的源码、候选产物、实跑命令和统计；一版后至多两轮有具体目标的修复 |
| Cursor / Grok 4.6 Extra High（资料） | 阅读照片与证据；补齐规格；独立比较参考图与候选；定位跨文件问题 | 来源和冲突、具体结构差异或修复建议；不得用“自评分很高”代替审查 |
| Grok Bot（本轮未启用） | 以后单个对象如财富广场等单个对象的独立资料任务，按视角和年代整理来源 | `reference-index.md`、更新的任务证据、来源允许保存的参考图、缺口清单；不依赖本机正在运行的游戏 |

这是起始分工，不是模型能力排名。先完成一个工具任务、一个资料任务、一个按规格建模任务，记录实际通过率、修复次数和总用量，再调整首选执行者。普通批处理直接运行脚本，避免让任何模型逐条重新推理。

## 额度要按实际用量池算

个人与团队计划中的 Composer 2.5、Cursor Grok 4.6 使用同一个 Cursor Models 池；切换模型不能当作另获一份额度。Composer 文档还区分标准与 Fast 价格，耗时批处理无需只追求最快响应，应按界面实际可选版本和用量核算。[Cursor 官方模型说明](https://prod.cursor.com/docs/models/cursor-composer-2-5)。

若现有每月 300 美元订阅是个人 SuperGrok Heavy，官方支持通过关联账号授予 Grok Bot 使用量；这不等于给 Cursor 编辑器增加同额模型额度。Cursor 计划与 SuperGrok 关联也不会叠加两份 Bot 额度。Bot 看自己的 Weekly usage，超出后的 On-demand 按 Cursor 设置计费；本次未查看或修改你的账号配置。[官方 Bot 计费说明](https://prod.cursor.com/help/grok-bot/plans)。

Bot 的执行环境是持久云端虚拟机，具有浏览器、文件与终端，并非自动共享这台 Mac 的项目目录。因此资料包适合直接交给它；本地 Blender 资产任务应留在已经配置好的 Cursor 环境，除非另行准备并验证云端构建环境。[Grok Bot 官方环境说明](https://docs.x.ai/grok-bot/overview)。

## 一次交付一个有边界的工作包

1. 集成人员固定输入版本、唯一对象、允许改动目录、预算和本轮阶段。同一楼的资料 → 规格 → 模型应串行，不要资料未定时让另一个 Agent 猜着建模。
2. 将对应 handoff 与其列出的必需输入交给执行者。Cursor 读取现有项目规则与少量样板；Bot 接文件包，不接整段历史对话或整座城市资产。
3. 不同对象可以并行，但每个文件只保留一个写入者。多个代码 Agent 使用独立分支/工作树；先固定当前可用基线，不能假设远程 main 包含尚未提交的本地修改。当前多个地标仍共用 `priority.py`，禁止并行写它。
4. 执行者提交一屏摘要：完成阶段、文件、产物、实跑检查、估计项、最多三个需判断问题。参考资料交回时保留来源 URL 与观察依据，不能只交一张拼图。
5. 初次建模或明显偏差才交另一模型比图；规格已稳定的批量变体优先脚本检查和抽样复核。避免每个小任务都让两个模型反复辩论。
6. 集成人员串行接入总资产、排除 ID、碰撞和渲染。目标电脑跑实际路线，不把 Blender 渲染或构建成功称为游戏验收通过。
