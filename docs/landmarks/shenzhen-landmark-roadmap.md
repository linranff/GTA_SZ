# 深圳重点地标清单与 GTA V 视觉升级路线

创建：2026-09-12。用户目标：建筑、车辆、行人、天空、道路、港口与交通设施的可见表现，以 GTA V 的成熟城市观感为开发标杆。执行模型统一为 Cursor Grok 4.6 / Extra High。本文是制作优先级和验收契约，不是官方地标排名，也不表示已达到 GTA V 画质。

## 执行原则

先完成一栋地标和它周围一段可信街景，再推广到下一栋。不要把清单当作一次性全城重建命令，也不要把楼做得很细、楼下仍留大片空地。每栋记录来源、基线、候选、问题、实际验收结果；一个正在制作的候选完成复核后，才给同一执行者下一栋。

顺序按现有资料、可复用工具、画面收益和当前地图覆盖确定。腾讯优先，是因为已有独立模块与较完整证据，候选工具正在以它为样板；春笋是紧接着的首要美术地标。财富广场资料可以并行，模型修改仍串行。若缺少关键证据或工具，记录具体阻塞，由集成人员决定调整顺序，不无限搜索、不悄悄换成猜测。

当前城市 WGS84 裁切为 `[113.915,22.497,114.135,22.575]`，依据 `public/city/city.json.meta`。有地理覆盖不等于已经建模；未发现具名资产也不等于底图里没有普通楼体。地图外地标先列为扩区候选，不能塞进错误位置。所有新对象先定位，再确定是否需要扩展路网、地形、海岸和分区加载。

## 持续保留的项目重点

财富广场和七街公馆/哈尔滨大厦继续精修，属于用户指定重点，不把它们包装成官方“全深圳最重要地标”。财富广场证据由当前 Grok 资料任务负责；七街公馆在轮到模型时单独拆出候选，避免并行修改共享 `priority.py`。

深圳湾公园、人才公园、莲花山、香蜜湖是景观/地形对象，分别验收海岸步道、树阵/水岸、山脊与地形起伏、城市绿地。它们不是建筑，不能用楼体的面数或六视角检查代替地面驾驶体验。

## GTA V 对标：把视觉目标变成可检查的项目

首轮以 GTA V PC 原版官方画面为视觉参考入口，后续选固定实机帧并标明版本、天气、时间、镜头。官方宣传截图只供构图和材料层次参考，不能推断性能；不混入未标注的画质 MOD。深圳保留自己的地理、路牌与美术身份，目标是可信、完整、连贯的城市表现。

| 系统 | 要求可见的结果 | 常见失败与复核方法 |
| --- | --- | --- |
| 地标建筑 | 远处轮廓可辨认；中距离有体块/材料层次；近处有窗框、入口、檐口、柱脚与落地关系 | 藏掉招牌仍应可辨识；不接受穿透、重叠旧楼、无厚度悬浮面；六视角加游戏街面检查 |
| 普通街区 | 办公、住宅、商业、工业各有结构逻辑；退界、屋顶、楼高和底层功能有变化 | 不用无限随机颜色掩盖同一盒子；一条街检查前中后景与可见重复率 |
| 主角与交通车辆 | 车身曲面连续；漆面、轮胎、玻璃、金属分别受光；灯壳和车灯可信 | 晴天/夜间/湿路、前后四分之三视角；检查反光跳变、法线接缝、比例与驾驶舱 |
| 行人 | 合理身材、头手脚与服装轮廓；运动有重心变化；人与地面接触可信 | 不要求首轮电影级面部；驾驶与步行距离看脚滑、穿插、浮空、同模同姿势集中重复 |
| 天空与自然光 | 太阳方向、云的明暗、环境补光、雾与远景一致；阴影中仍有材料细节 | 晴天不灰蒙，黄昏不全橙，夜间不靠提高曝光变白；不用饱和度/Bloom 代替光照 |
| 道路与人行空间 | 沥青、标线、路沿、人行道、井盖、排水和接缝有正确尺度与层次 | 地面不能只有大平面贴图；干燥路面不整条镜面，积水限定在合理位置，近中远不闪烁 |
| 植被 | 树种、冠幅、高低、枝叶透光有差异；绿化带连续且避让路口 | 不靠全城高模；近中远切换不突然缺树，树影与根部接地；草地起伏不穿路 |
| 红绿灯与路口 | 正确朝向与杆件尺度、灯壳、停止线、斑马线和信号状态 | 不把发光红绿点当完整设施；信号相位与车辆可见行为一致，交通逻辑由集成人员接入 |
| 海面与港口 | 海天色连续、远近反射过渡自然；码头有岸墙、船、岸桥、堆场、作业道路 | 不出现半圆蒙版边界；船尺度和吃水一致；港口不摆成零散道具展览 |
| 城市细节 | 路灯、护栏、店招、站牌、路牌、座椅等服务于街道功能 | 不靠无目的堆道具；文字可读且有依据，无悬浮/重复遮挡，少量损耗与污迹符合位置 |

声音与玩法也影响完整感，但本文件首先要求可见外观；没有做的系统保持待办，不能因静帧好看就声称整个游戏达到 GTA V。

## 城市系统怎样穿插实施

不能等 16 栋地标全部做完才处理街面。以下是样段里程碑，仍由主集成人员分派有明确文件所有权的工作包；除上述已派任务外，其余尚未启动。

| 里程碑 | 覆盖内容 | 交付门槛 |
| --- | --- | --- |
| A：腾讯与春笋样板 | 两栋楼分别通过轮廓/材质/入口复核，再补各自约 150–300 m 的可驾驶周边街面；这个距离是制作范围，不是测绘尺寸 | 同一路线有路沿、人行道、树阵、设施、接地阴影和近中远层次；远景、车外、街面三个高度成立 |
| B：一条完整生活街道 | 复用样板到福田一路段，加入普通楼原型、店面、路口灯杆与信号、交通车辆、行人 | 静帧可信，行驶过程中也没有突然切换、脚滑、浮空或明显重复；主角车的比例、灯具、漆面和驾驶舱另做独立候选 |
| C：全天候一致性 | 在 A/B 固定位置比较晴天、黄昏、夜间、雨天；把天空、自然光、道路与海面反射作为一个整体 | 不用一张夜景遮掉白天材料问题；反射和雾的边界连续；低中高维持相同美术关系 |
| D：扩区港口 | 选择一个经定位的蛇口/赤湾或盐田作业片区，先打通地图边界与加载，再组合岸墙、岸桥、集装箱、船、道路 | 有完整尺度和作业空间；具名港口位置正确；扩区性能通过后再推广 |

地标队列与这些里程碑穿插推进。每次共享 `src/` 的材质、天空、信号和加载改动只给一个集成人员；Grok 可交独立候选模型、参数建议或街段布置清单，避免三个任务同时改渲染器。RTX 3060 优先达标，高档不是全城同时堆高模；已有低中高配置继续保留。

## 每栋的执行与验收

1. **资料与基线：**核对地点、楼座、足印、尺寸来源，至少两个形体方向；保存当前模型/资料哈希和问题清单，避免把已经好的部分重做坏。
2. **候选：**先保轮廓与体块，再做材料和近景结构。源码、GLB、灰模/材质六视角都进独立候选目录；不修改公共 GLB 和共享渲染来让某栋截图好看。
3. **自检：**从实际 GLB 统计三角形、材质、字节与包围盒；检查法线、透明/不透明、重复面和轴向；至少提交三条可见差异与仍未解决的项。
4. **主集成人员复核：**同角度比较基线与候选，拒绝轮廓变差、玻璃发白/过黑、无依据灯光、旧楼叠加、截图与产物版本不一致。
5. **接入：**一个集成人员串行接入替换 ID、LOD、碰撞和加载，保存当前资产下的街面/远景/俯瞰，以及晴天/黄昏/夜间图片。单栋通过后才开始下一栋模型。
6. **性能：**同一路线测低/中/高档实际分辨率、draw calls、帧时间 P95/P99。RTX 3060 / 1080p / 60 fps 是目标；没有实测不得写通过。低档降计算和细节密度，保留辨识轮廓、道路和基本色彩关系。

候选预算先继承任务契约的 25,000 三角形 / 12 材质 / 8 MiB / 2048 贴图边长上限；这是首轮约束，不是达到 GTA V 的配方。现有对象超限时实报并提出简化或预算调整，不能篡改统计。远景优先合并、实例化和真实接入的 LOD；只多导出几份文件而运行时仍用高模，不算优化。
