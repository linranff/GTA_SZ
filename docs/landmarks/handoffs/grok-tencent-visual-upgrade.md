## 本轮的具体目标

- 保留有依据的双塔尺度、朝向、三个连廊的高低及端部关系；任何改动必须说明当前证据为什么支持，不能把估计升级为测量。
- 分离整体幕墙、较暗玻璃、框架/金属、屋顶设备、连廊外壳与底面。避免整栋单色高反射、错乱窗格、纯白金属和薄片般的连廊。
- 优先增强中近景可见的几何厚度、窗框深浅、连廊端部、入口与首层结构。不要逐窗添加高面数盒子；细小窗格和重复构件优先利用现有材质/UV与低面几何。
- 首层入口、雨篷、柱脚等只在来源可定位时制作；未知背面采用明确说明的简化。腾讯既有字牌资产与定位由现有管线处理，不在候选中重新发明 Logo 或夜间发光。
- 不靠提高全局曝光、Bloom、饱和度或给整栋加透明来制造“高级感”。候选应在中性光和当前游戏日夜光照下成立。

## 交付与通过条件

1. `spec.md`：最多五项优先缺陷，每项给源码/现有视图与参考来源、要改什么、如何判断；已确认事实、估计与未知分开。
2. `source-index.md`：复用及新增来源、实际看过的图、日期/方向/支持部件；未能打开的记录失败，不捏造观测。
3. 独立候选模块保留 `build(b,lm,spec,scale=0.6)` 接口和现有坐标约定，参数与来源可追踪。不要把 WGS84、游戏坐标和真实米再缩放两次。
4. 工具可用后，用完全相同机位、灯光、输出尺寸生成基线与候选灰模/材质视图，并从实际 GLB 统计资源；三角形/材质/字节不可抄旧报告。是否支持候选模块以工具实际接口为准，不猜参数。
5. `review.md` 逐项比较比例、轮廓、框架、连廊、材料和入口；写出仍需改进处，不能只写“更精细”“达到 AAA”。
6. 候选预算继承既有任务上限：25,000 三角形、12 材质、8 MiB、贴图边长 2048。实际超限先报告，并给简化/预算调整建议，不自动扩预算或伪造 pass。
7. 公共资产/只读输入不变，候选产物与检查有哈希对应。没有游戏 GPU 截图就写“候选待集成”，RTX 3060 未实测就写“性能待验收”。

本轮一版加最多两轮针对具体差异的修复。不需要用户再次批准上述候选工作；主集成人员负责规格争议、共享接入和最终外观复核。第一栋交回后等具体反馈，不自动修改第二栋春笋或整张清单。
