# 普通楼立面重复：原因与候选修复

2026-09-05。本轮只增加独立候选脚本、材质插件和审查文件；不覆盖另一任务维护的材质控制器、着色器脚本、`public` 或地标。

## 已核实的原因

| 位置 | 实际实现 | 对截图的影响 |
|---|---|---|
| `scripts/prepare_driving_city.py:92` | `typ='office' if h>48 or ... else 'residential'` | 全城16076片仅3991片office、12085片residential，stone为0。回查已有OSM源，2005片office的原标签其实是apartments/residential/house/dormitory。高层住宅被贴了办公幕墙。 |
| `scripts/city_mesh.py:68` | 每条墙边从U=0开始，宽和高度均除24 | 每栋在相同高度重复同一窗格、同一亮灯位置；只换颜色不会改变这个问题。 |
| `src/city-architecture-materials.ts` | 普通楼按原材质名统一映射到office/residential/stone三族 | 已正确修复白屋顶、黑玻璃、物理参数和纹理资源释放；但是普通楼实际上只用到前两族。地标的独立玻璃参数是有效进展。 |
| `scripts/make_architecture_windows.py` | 每张图只有一份固定稀疏窗灯mask | 发光与窗对齐了，但只要同UV相位就还是同一栋楼的复制。 |
| `scripts/build_city_facades.py:18–24` | VertexColor经MixRGB乘法连接 | 当前public原资产的普通材质丢失baseColorFactor；原始导出颜色未正确保留。另一任务提供的12色候选修复了COLOR_0，但不修改UV/用途。 |

不能把“12种色彩”“8种艺术类型”说成每栋真实建筑已做测绘还原。源普通楼有15384个真实ID，部分是同一建筑的多个裁剪片。共享顶点会迫使相邻对象共用同一颜色或立面族。

## 本轮候选

- `scripts/prepare_facade_diversity.mjs`：以已审查的`artifacts/materials/buildings-tinted.glb`为输入；按OSM id找回本机已有的`data/processed/shenzhen_study/buildings.geojson`用途。高层住宅不会因高度自动变成办公幕墙。缺少用途的对象采用明确标注的艺术分类。
- `scripts/make_facade_diversity_atlas.py`：手工参数化绘制八种窗墙语法，分别为竖梃幕墙、横向带窗、暖色住宅、象牙白板楼、石材商住、陶砖低层艺术类型、工业厂房、旧式灰阳台住宅。不是八个随机Hue。
- `src/city-facade-diversity.ts`：共享PBR插件，用同一张图集选择各栋立面族，按稳定建筑seed和墙面方向改变UV相位，逐窗选择占用、亮度与色温。沿用当前黄昏/夜景切换。图集alpha保存玻璃/墙体粗糙度，不增加额外粗糙度贴图或采样。

输出目录为`artifacts/materials/facade-diversity/`。`buildings-varied.report.json`记录当前候选哈希、几何保持摘要、家族分布、来源分类、匹配缺口。`atlas-report.json`记录两张新图及预算。不要沿用早期报告里的旧SHA，应读取最终文件。

## 接入契约

```ts
// city-world constructor, after createArchitectureMaterials
this.facadeDiversity = createFacadeDiversity(this.scene);

// generic buildings loader, after this.architecture.applyMeshes
this.facadeDiversity.applyMeshes(result.meshes, name);

// toggleLight, after this.architecture.setNight
this.facadeDiversity.setNight(this.night);
```

集成人员串行将候选`buildings-varied.glb`安装为`public/city/buildings.glb`，复制两张PNG至`public/city/textures/architecture/`，再更新building-exclusions及资产交付哈希。`facades.glb`与流式小块不加新顶点属性，保留现状。

**保留原材质模块的albedo/emissive引用。** 它们负责Babylon的ALBEDO/EMISSIVE宏和旧资产/新图加载失败的回退；插件只替换有TEXCOORD_1的普通`block_*`墙面的两次采样，不复制材质，不影响具名地标、屋顶、地面、植物、车辆。原模块异步更新纹理或setNight不会覆盖插件的共享图集采样。后续可由材质owner进一步减少不用的旧纹理；本轮不触碰其引用计数。

输入新增的`TEXCOORD_1`为float2：x=family+.25，y=稳定seed。每个三角形的两个值必须完全一致，禁止插值穿过不同家族；有共享顶点的对象合组，不拆几何。POSITION、NORMAL、UV0、COLOR0、indices、材质和node变换经过写出再读的哈希保持检查。

## 预算与验收

- 两张共享图：1024² RGBA albedo/roughness + 512² RGB窗玻璃stencil，按RGBA8及完整mip保守估算**6.67 MiB**。增加0灯、0几何、0渲染通道、0 draw call。
- 只给1318939个有UV的普通墙面顶点增加float2，约**10.06 MiB**。未给另外461万普通楼无UV顶点或近景立面增加属性。
- 图集先fract各楼局部UV，再寻址族单元，并保留8像素边界；不能把UV缩到图集格后直接让纹理全图repeat，否则会跨到别的建筑族。
- 发光从最终玻璃颜色stencil裁切；框、石材、空调和防盗栏不发光。室内占用是艺术模式，不是真实住户数据。
- `scripts/check_facade_diversity.mjs`验证高层住宅分类、工业类别、确定性、插件采样替换、UV2、地标排除和NullEngine着色器预处理；**不等价于GPU编译/画面/帧率通过**。

集成后仍必须检查深圳湾同机位近景、车后第三人称、无人机中景，确认住宅和办公窗墙比有明显不同、随机灯窗没有跨墙、图集mip不串格、没有透明建筑。再测出生点和高空视角实际FPS与p95。严格以当前GLB哈希的浏览器结果报告；本任务未启动Chrome或Blender。

本轮仍未完成：逐栋真实颜色/窗格测绘、城中村街段具名还原、立面凹凸几何类型全覆盖。近景普通楼仍沿用原有部分阳台和竖梃，和新的窗格可能存在尺度冲突，需视觉复核后局部调整。
